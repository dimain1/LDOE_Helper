# Use-case specification

## UC-003 Создать событие

ID: UC-003
Название: Создать событие
Акторы: Пользователь
Уровень: пользовательский
1. Краткое описание: Создание события пользователем через приложение или overlay с указанием имени события, времени через которое оно произойдёт.

2.	Предусловие:
- Пользователь должен быть авторизован.

3.	Постусловие:
- Запись о создании события сохраняется локально.
- Событие сохранено.
- Запланировано уведомление.

4.	Основной поток:
    1.  Пользователь инициирует процесс создание события.
    2. 	Пользователь вводит параметры события.
    3.	Пользователь подтверждает создание события.
    4.	Система валидирует параметры.
    5.  Система сохраняет запись о событии.
    6.  Система создаёт таймер на уведомление.
    7.	Система отображает пользователю подтверждение о создании события.

5.	Подпотоки:

5.1. Подпоток A: Создание события через приложение

-   A1. На шаге 1 инициация происходит в приложении.
-	A2. Инициация происходит через интерфейс приложения.
-	A3. Продолжение с шага 2 основного потока.

5.2. Подпоток B: Создание события через overlay.

-   B1. На шаге 1 инициация происходит в overlay.
-	B2. Инициация происходит через overlay-интерфейс.
-	B3. Выбирает создание события.
-	B4. Продолжение с шага 2 основного потока.

6.	Потоки исключений

6.1. Исключение E1: Некорректные данные.

-	E1.1. На шаге 4 система обнаруживает некорректные параметры. 
-	E1.2. Система уведомляет пользователя.
-	E1.3. Возврат к шагу 2 основного потока.

6.2. Исключение E2: Ошибка сохранения.

- E2.1. На шаге 5 возникает ошибка сохранения.
- E2.2. Система уведомляет пользователя.
- E2.3. Сценарий завершается без создания события.

Приоритет: высокий
Частота использования: часто
Сложность: средняя


## UC-007 Добавить контент

ID: UC-007
Название: Добавить контент
Акторы: Администратор
Уровень: Пользовательский
1. Краткое описание: Администратор добавляет новые данные в базу знаний приложения

2.	Предусловие:
- Администратор должен быть авторизован.
- Сервер должен быть доступен.

3.	Постусловие:
- Контент сохранён.
- Обновлена версия данных.

4.	Основной поток:
    1.  Администратор инициирует процесс добавления контента.
    2. 	Администратор вводит данные.
    3.  Администратор подтверждает добавление.
    4.	Система валидирует данные.
    5.  Система сохраняет данные.
    6.  Система обновяет версию данных. 
    7.	Система отображает подтверждение добавления контента.

5.	Подпотоки:

5.1. Подпоток A: Ввод данных через форму

- A1. На шаге 1 администратор открывает форму добавления контента
- A2. На шаге 2 администратор вручную вводит данные контента
- A3. Переход к шагу 4 основного потока

5.2. Подпоток B: Добавление через импорт

- B1. На шаге 1 администратор выбирает режим импорта данных
- B2. Администратор загружает файл или вводит структурированные данные
- B3. Система извлекает данные и переходит к шагу 4 основного потока


6.	Потоки исключений

6.1. Исключение E1: Некорректные данные

-	E1.1. на шаге 4 система обнаруживает что данные некорректы
-	E1.2. Система уведомляет администратора
-	E1.3. Возврат к шагу 2 основонго потока

6.2. Исключение E2: Сервер не доступен

- E2.1. На шаге 4-6 происходит ошибка со стороны сервера
- E2.2. Система отобржает "Ошибка сервера, повторите позже"
- E2.3. Прецендент завершается неудачей

Приоритет: высокий
Частота использования: часто
Сложность: средняя
