# ADR-004: Стратегия offline-first (Room)

## Статус
Принято

## Контекст

Приложение LDOE-Helper используется во время игры в LDOE, которая сама потребляет интернет-трафик. Мобильное соединение может быть нестабильным. Функциональность просмотра справочника и управления событиями должна работать без сети.

## Решение

Применить стратегию **offline-first** с использованием **Room Database** как единственного источника данных для UI:

1. Данные с сервера при получении сохраняются в Room (`upsert`, `OnConflictStrategy.REPLACE`).
2. UI всегда читает из Room через `Flow<>` — реактивное обновление.
3. При наличии сети запускается синхронизация в фоне (Retrofit → Room).
4. События и шаблоны создаются сначала локально, затем синхронизируются с сервером.

## Обоснование

- Приложение работает без задержек: UI не ждёт ответа сервера.
- WorkManager планирует уведомления на основе локальных данных — не зависит от сети.
- `Flow<>` в Room обеспечивает автоматическое обновление UI при изменении кэша.
- Android Jetpack Room — рекомендованное решение Google для локального хранения.

## Последствия

- Необходима стратегия разрешения конфликтов при рассинхронизации («сервер побеждает»).
- Дублирование схемы: Room Entity ≈ Server Entity (разные классы).
- При первом запуске без интернета справочник пуст — необходимо UX-сообщение.

## Альтернативы

| Альтернатива | Причина отклонения |
|-------------|-------------------|
| Online-only (Retrofit) | Не работает без сети; неприемлемо для целевого сценария |
| SharedPreferences | Не подходит для реляционных данных |
| DataStore | Предназначен для настроек, не для коллекций сущностей |
