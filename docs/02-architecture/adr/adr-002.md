# ADR-002: Выбор СУБД (PostgreSQL)

## Статус
Принято

## Контекст

Серверная часть хранит структурированные данные (пользователи, события, шаблоны) со связями и игровой контент с разнородными атрибутами (у локации — параметры отката, у рецепта — список ингредиентов). Требуется реляционная СУБД с поддержкой гибких структур.

## Решение

Использовать **PostgreSQL 15** в качестве основной СУБД.

## Обоснование

- Полная поддержка реляционной модели и внешних ключей.
- **JSONB** позволяет хранить произвольные атрибуты игрового контента в колонке `attributes` без изменения схемы при добавлении нового типа объектов.
- Зрелость, надёжность, активная поддержка.
- Поддерживается Spring Data JPA / Hibernate без дополнительных драйверов.
- Официальный Docker-образ `postgres:15-alpine` — лёгкий деплой.

## Последствия

- Требуется настройка `PostgreSQLDialect` в Hibernate.
- Сложнее в развёртывании, чем встроенная SQLite.
- `ddl-auto=update` допустимо на разработке, но в production необходимо заменить на Flyway/Liquibase.

## Альтернативы

| Альтернатива | Причина отклонения |
|-------------|-------------------|
| SQLite | Не предназначена для серверного использования; нет JSONB |
| MySQL | Менее гибкая работа с JSON; меньше возможностей для аналитических запросов |
| MongoDB | Гибкая схема, но сложнее поддерживать связи между документами |
