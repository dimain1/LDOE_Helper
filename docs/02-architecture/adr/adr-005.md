# ADR-005: Контейнеризация через Docker Compose

## Статус
Принято

## Контекст

Серверная часть (Spring Boot + PostgreSQL) должна быть легко развёртываема на VPS с минимальными ручными настройками. Окружение разработки должно максимально совпадать с production.

## Решение

Использовать **Docker Compose** для оркестрации двух сервисов:
- `ldoe-db` — `postgres:15-alpine`, данные в томе `pgdata`.
- `ldoe-backend` — кастомный образ из `Dockerfile` в `Backend/backend/`, зависит от `ldoe-db`.

Конфигурация передаётся через `.env`-файл (не фиксируется в репозитории).

## Обоснование

- Воспроизводимое окружение: `docker-compose up -d` поднимает весь стек.
- Изоляция: бэкенд и БД общаются по внутренней Docker-сети; внешне доступен только порт 8080.
- `healthcheck` на `ldoe-db` гарантирует, что бэкенд стартует только после готовности PostgreSQL.
- Тома `pgdata` и `uploads` сохраняют данные между перезапусками контейнеров.
- `.env` позволяет менять конфигурацию без пересборки образа.

## Последствия

- Требуется Docker и Docker Compose на VPS.
- При пересоздании тома `pgdata` данные теряются — необходим план резервного копирования.
- Горизонтальное масштабирование требует вынести изображения в S3 и БД — в managed service.

## Альтернативы

| Альтернатива | Причина отклонения |
|-------------|-------------------|
| Bare metal (установка вручную) | Трудно воспроизвести; зависимость от ОС сервера |
| Kubernetes | Избыточен для монолитного сервиса на текущем этапе |
| Облачный PaaS (Heroku, Railway) | Платный или с ограничениями free tier; меньше контроля |
